# Jira and Confluence OAuth sessions — Mojolicious::Lite

A small external web app for current self-hosted Jira and Confluence Data Center.
It uses OAuth 2.0 authorization code + PKCE (S256), READ scope, and the products'
own `/rest/oauth2/latest/authorize` and `/rest/oauth2/latest/token` endpoints.
It does not use Atlassian Cloud, service-account impersonation, passwords, or PATs.

## Session model

```
Server memory: sessions{random_sid}{connections}{jira}{tokens}
Server memory: sessions{random_sid}{connections}{confluence}{tokens}
Browser cookie: signed {sid => random_sid}
```

Each browser session has independent product connections, access tokens, refresh
tokens, OAuth state, PKCE verifiers, and CSRF token. The registered application
client ID/secret is shared configuration identifying the app; the resulting user
tokens are separate per session. Different users' requests explicitly attach their
own bearer token. The shared HTTP client never has a default bearer token or a
product login cookie.

Mojolicious' usual session cookies are signed, not necessarily encrypted. This app
therefore stores **only an opaque session ID** in that cookie. OAuth credentials
remain in memory and are never rendered in the page. The cookie is HttpOnly,
SameSite=Lax, Secure with an HTTPS APP_BASE_URL, and has no persistent expiry.

Tabs in one browser profile share cookies and therefore share this session. Use
different browser profiles or a private window to demonstrate two users. The
account chosen at the product's login/consent screen determines the API identity.
This demo has no separate app login; add your corporate login before linking it
to a larger app, and clear/rotate the app session when changing local identities.

## 1. Register two incoming application links

An administrator configures an External application / incoming OAuth 2.0 link in
each product's Administration → Application links. Exact UI labels can vary.

| Product | Redirect URL (must match exactly) | Allowed scope |
| --- | --- | --- |
| Jira | `https://oauth-demo.example.internal/oauth/jira/callback` | `READ` |
| Confluence | `https://oauth-demo.example.internal/oauth/confluence/callback` | `READ` |

Record the client ID and client secret generated by each link. Each user then
authorizes the registered application individually. The app can access only what
that user can access within the permitted scope.

## 2. Install and configure

Requires Unix/Linux (uses `/dev/urandom`), Perl 5.20+, Mojolicious 9.40+, and
IO::Socket::SSL for HTTPS. From this directory:

```sh
cpanm --installdeps .

export APP_BASE_URL='https://oauth-demo.example.internal'
export SESSION_SECRET="$(perl -MMIME::Base64=encode_base64 -e 'open my $f,"<:raw","/dev/urandom" or die; read($f,my $b,48)==48 or die; print encode_base64($b,"")')"
export JIRA_BASE_URL='https://jira.example.internal'
export JIRA_CLIENT_ID='your-jira-client-id'
export JIRA_CLIENT_SECRET='your-jira-client-secret'
export CONFLUENCE_BASE_URL='https://wiki.example.internal/confluence'
export CONFLUENCE_CLIENT_ID='your-confluence-client-id'
export CONFLUENCE_CLIENT_SECRET='your-confluence-client-secret'

perl app.pl daemon -l http://127.0.0.1:3000
```

Serve the public APP_BASE_URL over HTTPS through your reverse proxy to this
single local daemon. The configured URL, rather than the inbound Host header,
determines callback URLs. APP_BASE_URL must have no path prefix. Product base
URLs may include context paths such as `/jira` or `/confluence`; do not include
`/rest` in the base. Limit access to the backend listener to the proxy/host.

Alternatively run the daemon with its HTTPS listener and your certificate/key:

```sh
perl app.pl daemon -l 'https://0.0.0.0:3000?cert=/path/server.crt&key=/path/server.key'
```

In that case APP_BASE_URL and the registered redirects must include the actual
public host and port. Use your enterprise CA trust configuration as needed
(Mojo::UserAgent supports MOJO_CA_FILE). TLS verification stays enabled.
Keep real secrets out of source control and shell history; the exports above
illustrate the names. A protected service environment file is suitable for a demo.

## 3. Use it

1. Open APP_BASE_URL and select **Connect Jira**.
2. Sign in on your Jira site and approve the request.
3. Use **View my profile JSON** to call `/rest/api/2/myself` as that user.
4. Connect Confluence separately. Its profile example calls `/rest/api/user/current`.
5. Open a separate browser profile, connect a different product user, and compare.

| App route | Purpose |
| --- | --- |
| `GET /` | Show connection status and forms |
| `POST /connect/:provider` | Begin authorization (CSRF protected) |
| `GET /oauth/:provider/callback` | Validate state and exchange code using PKCE |
| `GET /api/:provider/me` | Fetch the current product user's profile |
| `POST /disconnect/:provider` | Forget that product's session credentials |
| `POST /logout` | Destroy this app session and both connections |

`:provider` is `jira` or `confluence`. To add another read API example, follow
`/api/:provider/me`: obtain `access_token_p`, then attach the returned token to
that individual HTTP request. Do not accept arbitrary upstream URLs from users.

## Expiry, refresh, and limits

- Session inactivity expires after 30 minutes; absolute lifetime is 8 hours.
  Override with SESSION_IDLE_SECONDS and SESSION_MAX_SECONDS (positive seconds).
  Expiry is checked on requests and memory is swept once per minute.
- A token within 30 seconds of expiry is refreshed before the API request.
  Both replacement tokens are saved together. Concurrent requests in one
  session/product share a single refresh promise.
- API HTTP 401 clears the connection; HTTP 403 preserves it and reports denial.
  A failed refresh returns a generic HTTP 502; retry or reconnect. Provider bodies
  and raw exception text are not sent to the browser or logged by this app.
- Disconnect/logout forget tokens locally. They do not sign the user out of
  Jira/Confluence or revoke the upstream OAuth grant. An already dispatched HTTP
  request can finish; its result is not delivered after the session ends.
- Closing a browser does not notify the server, and browser session restoration
  can restore session cookies. Use End session for explicit cleanup; server idle
  and absolute limits apply independently of browser behavior.
- Restarting the process clears all connections. Use **one daemon process**.
  Do not run this memory-backed demo with Hypnotoad, prefork workers, replicas,
  or a reloader. A deployment with multiple workers needs a shared server-side
  session store, token encryption at rest, and a distributed refresh lock.
- The demo returns JSON for profile requests; it intentionally has no database,
  persistent credentials, background access after logout, or user directory.

## Tests (no Atlassian instance needed)

```sh
prove -v t/oauth.t
```

The test uses a loopback mock OAuth provider and the real Mojolicious routes,
cookies, callback processing, HTTP token exchange, and API calls. It verifies
two-user and two-product isolation, PKCE, CSRF/state rejection, one-time callbacks,
cookie contents, refresh/rotation and concurrency, errors, disconnect, and logout.
ALLOW_LOOPBACK_HTTP=1 is for these local tests only; it permits HTTP only for
localhost/loopback URLs. Real product deployments should use HTTPS.

These tests do not replace a live integration check against your configured Jira
and Confluence installations; no live Atlassian system was available for validation.
